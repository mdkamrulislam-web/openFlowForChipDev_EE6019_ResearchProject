## Tasks Done

- **Core and width chosen: FazyRV, 4-bit data path** (`CHUNKSIZE = 4`, `CONF = MIN`, register file in block RAM). I also built the 8-bit version for comparison. The system around the core is the authors' reference SoC (4 KB RAM, GPIO) plus my own board wrapper (reset synchroniser, switch synchroniser).
- **Verified in simulation (Vivado xsim):** the 40 RV32I instruction tests from the FazyRV repository pass for 4-bit and 8-bit. Measured cycles per instruction on a simple loop: **10 (8-bit) and 16 (4-bit)**.
- **Full Vivado flow on the PYNQ-Z2 (xc7z020), 125 MHz board clock:**

  | Version | Fmax | LUTs | Flip-flops | Slices |
  |---|---|---|---|---|
  | 8-bit, default settings | 96.5 MHz (fails 125 MHz) | 484 | 281 | 142 |
  | 4-bit, default settings | 121.5 MHz (fails by 0.23 ns) | 343 | 261 | 113 |
  | 4-bit, performance settings | 125.1 MHz (meets) | 387 | 269 | 117 |
  | 4-bit, performance settings, 7.5 ns target | 133.4 MHz | 393 | 273 | 119 |

  These are for the whole SoC, not the core alone (the paper gives 87 slices for the 4-bit core on 7-Series). The critical path runs from the instruction decoder through the branch logic to the program counter, and about 75% of its delay is routing.
- **Power measured with the real switching activity, not a guess.** I built a flow that simulates the routed netlist running a fixed workload (CRC-32, sort, checksum, checked against a Python model), records the activity of every net (SAIF) and reads it into Vivado's power report. Result for the 4-bit baseline: **12 mW dynamic** (confidence High); Vivado's default vectorless estimate said 18 mW. Static power is 0.103 W, but that is the whole chip's leakage, not the core's.
- **First low-power technique: redundant read elimination in the register file.** The power breakdown showed that the register-file RAM was read in **90% of all clock cycles**, although the core only needs the register values a few times per instruction. I changed the RAM so that it reads only when the read address changed or after a write (otherwise its output register already holds the right value). The output is identical in every cycle.

  | | Baseline | With the change |
  |---|---|---|
  | Register-file reads per workload pass (4-bit) | 340,558 | 72,058 (−79%) |
  | Same, 8-bit | 204,218 | 72,058 (−65%) |
  | Dynamic power (4-bit, activity-based) | 12 mW | 9 mW (about −25%) |
  | Cost | | +1 LUT, +5 flip-flops; timing still met |
  | Cycles per pass | 376,764 | 376,764 (identical) |

  All 40 instruction tests and my system test benches give identical results, cycle for cycle.

## Problems and how I handled them

- **The board stops after a few seconds.** On the PYNQ-Z2 the processor runs correctly, then stops at a random moment. I added diagnostic LEDs and found: the board clock keeps running, there is no reset, and the processor really stops. It happens with the original core too, and at 100 MHz and 25 MHz (so not timing). Every simulation of the same design, including the routed netlist, runs more than 1,500 workload passes without error. **Not solved yet.** I suspect the board (powered only from the laptop USB); next I will try the external supply, a lab board, and the on-chip logic analyser (ILA).
- **FPGA power is dominated by the chip's leakage** (0.10 W for the whole Zynq), so the saving shows in the dynamic power only. Vivado reports power in whole milliwatts, so I also count the RAM reads directly; that count is exact.
- **Vivado's simulation launcher fails on this laptop** ("spawn failed"), so I run the netlist simulation directly in xsim with my own scripts.
